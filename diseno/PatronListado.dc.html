El estado vive en la URL, no en el componente

La page lee searchParams en el servidor y se los inyecta al componente. Cada filtro, cada orden y cada pagina es un enlace: se puede compartir, guardar en marcadores y volver atras con el boton del navegador.

/dashboard/usuarios?busqueda=ana&tipo=trabajador&estado=activo&orden=nombre&dir=asc&pagina=2&porPagina=20

Lo que recibe por props

La page consulta el modelo e inyecta. El componente no sabe de que modulo se trata.

// definiciones, no datos
columnas: [
  { clave: "nombre", titulo: "Persona",
    ordenable: true, render: fn },
  ...
]
filtros: [
  { clave: "tipo", titulo: "Tipo",
    opciones: [...] },
  ...
]

// datos ya consultados
filas: Usuario[]
total: 47
pagina: 1
porPagina: 20

// estado leido de la URL
busqueda: "ana"
orden: "nombre"
direccion: "asc"

// accion principal, opcional
accion: { texto, icono, href }

Que aporta cada modulo

  • 1
    Sus columnas
    Que se muestra y como se pinta cada celda
  • 2
    Sus filtros
    Las opciones propias de la entidad
  • 3
    Su consulta
    Una funcion del modelo que ya acepta filtros, orden y pagina
  • 4
    Su panel de alta
    Solo el contenido del formulario; el panel es el mismo

El panel lateral tambien es unico

El mismo contenedor deslizante sirve para crear y para editar en cualquier modulo: cabecera con titulo y descripcion, cuerpo con el formulario que le pase el modulo, y pie con cancelar y confirmar. Se abre y se cierra con la URL, igual que los filtros.

/dashboard/usuarios?panel=nuevo
/dashboard/usuarios?panel=editar&id=12
